# Household Inventory

Tracks a household's Supplies and Assets from Android phones, synced with a server on the home network. What v1 does is in [docs/spec/v1.md](docs/spec/v1.md); domain terms are in [GLOSSARY.md](GLOSSARY.md).

## Layout

```text
apps/
├── mobile/     # Expo (React Native) Android app
├── server/     # Fastify API; also serves the built web app
└── web/        # React + Vite dashboard and download page
packages/
└── shared/     # types, Zod schemas and rules shared by server, web and app
```

## Development

Needs Node 24, pnpm 10 and Docker Desktop.

```sh
cp .env.example .env      # then set POSTGRES_PASSWORD (and the same password in DATABASE_URL)
pnpm install
pnpm db:up                # PostgreSQL in Docker on port 5432
pnpm db:migrate           # apply database migrations
pnpm dev                  # server on :3000, web on :5173 (proxies to the server)
pnpm test                 # all tests
pnpm typecheck
```

To run the production-like stack (server + built web + database) at http://localhost:8080:

```sh
docker compose up --build
```

New migrations: change `apps/server/src/db/schema.ts`, then `pnpm --filter @inventory/server db:generate`.

## Android app

`apps/mobile` is an Expo app (see its `AGENTS.md` before changing Expo code). The `android/` folder is generated by `expo prebuild` and never committed.

Building the APK needs, on the dev PC:

- **JDK 17**, with `JAVA_HOME` pointing at it.
- **Android SDK command-line tools**, with `ANDROID_HOME` pointing at the SDK and its licences accepted (`sdkmanager --licenses`). Gradle downloads the platform and build-tools it needs on the first build.

```sh
pnpm --filter @inventory/mobile build:apk     # → apps/mobile/dist/inventory-<version>.apk
pnpm --filter @inventory/mobile android       # build and run on a phone connected by USB (USB debugging on)
pnpm --filter @inventory/mobile start         # dev server for an installed development build
```

Release builds are signed with the debug key until the household's release key is set up.

On Windows, run Expo commands from a path with an uppercase drive letter (`E:\…`, not `e:\…`): Metro and Expo Router build broken paths otherwise ("None of these files exist: …\_layout.tsx"). `build:apk` corrects this itself.

Local database changes: edit `apps/mobile/src/db/schema.ts`, then `pnpm --filter @inventory/mobile db:generate`.

## Deploying and operating

The home server runs `compose.yaml` from `/srv/inventory`, with its `.env` (database password, `TZ`, `APP_VERSION`). Everything it keeps lives there: `db/`, `photos/`, `apk/` and `backups/`. First-time setup is a step-by-step wizard (see "First server setup" below).

- **Deploy** from the dev PC: `pnpm run deploy`. It bumps the version, asks for a one-line "what's new", builds the APK and the image, copies them over SSH (`DEPLOY_HOST` in `.env`), and starts the new version. Commit the version bump afterwards. `pnpm run deploy -- --dry-run --notes "…"` prints the steps without running them.
- **On start** the app takes a backup, applies pending migrations, then serves. If a migration fails, the container stops and leaves `MIGRATION_FAILED`.
- **Backups** run nightly at 03:00 inside the app: `pg_dump` plus the photos, kept 14 days, copied to the USB drive (it needs the `.inventory-backups` marker file). The dashboard footer shows the last result. `pnpm run backups:pull` copies them to this PC.
- **Restore** on the server: `scripts/restore.sh <backup folder>`. It replaces the database and photos, and phones sync everything again.
- **Roll back** on the server: `scripts/rollback.sh`. It starts the previous image, first restoring the pre-migration backup if the current version changed the database.
- **On the dev PC**, `compose.override.yaml` is merged in automatically: `docker compose up -d --build` builds from source and serves on http://localhost:8080 with Docker volumes and no USB drive.

## First server setup

Run once, from the repo root on the dev PC, in Git Bash: `scripts/setup-server.sh`. It walks through each step and can be re-run (it keeps what's already done):

1. Checklist, and the server's login name.
2. Reserving the server's address in the router (writes `SERVER_IP` and `DEPLOY_HOST` to `.env`).
3. An SSH key from this PC.
4. Docker on the server.
5. `/srv/inventory` and the server's `.env`, with a new database password for your password manager.
6. ufw: ports 80 and SSH, from the home network only.
7. The USB backup drive: formatted as ext4 if needed (with a confirmation), mounted at `/mnt/inventory-usb`, and marked for backups.
8. The app's release signing key, kept in `~/.inventory/` outside the repo. Its password goes in your password manager and is never stored on disk.
9. A Windows Firewall rule so phones can reach the dev server.
10. The first `pnpm run deploy`.
11. A test backup and restore.
12. Copies of the backups and the signing key off the server.
